# Security

## Reporting a vulnerability

Email **john.kang@snowflake.com**. Please do not open a public issue for a
security problem.

This is a reference implementation, not a supported Snowflake product. There is
no SLA on a response, and no guarantee of a fix.

## What this repository contains

- Entirely synthetic data. The 3PL fulfilment dataset is generated by
  `python/generate_data.py` and models no real organisation. There is no
  customer data, and no personal data of any kind.
- No credentials. Every connection is resolved through
  `~/.snowflake/connections.toml` by name; nothing is read from a committed
  file and no token, key, or password is stored in the repository.

## If you run this

Two things in the build are deliberately permissive because it is a demo, and
should not be copied into anything real:

- **`ACCOUNTADMIN`** is used throughout, because `EXECUTE_AI_EVALUATION`
  requires `CREATE DATASET ON SCHEMA` plus `EXECUTE TASK ON ACCOUNT`. Scope this
  down for any non-demo use.
- **A `0.0.0.0/0` user-level network policy** is suggested in
  `docs/GOTCHAS.md` #11 as a way to work around an account-level policy. That is
  appropriate for a personal demo account and nowhere else. Use real CIDRs
  otherwise.

Run `sql/AGENT_EVAL_DEMO_TEARDOWN.sql` to remove every object this demo creates.
